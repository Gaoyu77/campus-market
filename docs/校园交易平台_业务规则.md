# 同学集市：业务规则

本文件记录课程设计的实际方案，并非老师额外提出的要求。系统使用 SQL Server 和本机网页演示商品、收藏与订单的数据变化。

## 演示身份

- 页面可切换“小高同学”和“小张同学”；演示用户存放在 `Users` 表中。
- 不提供用户注册或登录。切换身份用于模拟买卖双方，并非真实身份认证；远程演示入口使用共享密码，持密码者均可切换身份并修改演示数据。
- 旧商品保留原示例卖家，无法切换身份的旧卖家商品暂不能预约。带【演示】标记的新商品可用于交易演示。

## 商品与收藏

- 一件闲置对应一条商品，商品归属于一个用户。名称、分类、成色、价格、校区和描述必填；价格为 0 至 999999 元，最多两位小数。
- 商品封面可选一张 JPG、PNG 或 WebP，最大 10 MB；发布后保存在本机数据库。未选择照片时使用示意图。
- 商品状态为在售、已下架、已预订或已售出。公开列表默认只显示在售商品；关闭“只看在售商品”可看到已预订和已售出商品。
- 卖家可以编辑、下架在售商品，或编辑、重新上架已下架商品。已预订和已售出商品不能编辑或上下架。
- 收藏记录属于当前演示身份，保存在 `Favorites` 表，刷新仍在；同一用户对同一商品最多收藏一次。商品下架后公开列表不展示，但在收藏列表中标为已下架，可取消收藏。

## 预约与订单

- 仅演示校园当面交易，不接真实支付和聊天；卖家不能预约自己的商品。
- 买家预约在售商品后，创建一条订单，商品变为已预订；同一商品最多有一笔有效预约。
- 买家或卖家可以取消有效预约，订单变为已取消，商品恢复在售；卖家可以确认完成，订单变为已完成，商品变为已售出。
- 订单保留预约时的价格。只有对应的演示买家或卖家可以执行相应操作；身份切换本身不是认证。
- 订单金额通过数据库 CHECK 约束限制为非负数。
- 商品状态和订单状态在同一数据库事务中更新，失败时一起回滚。
- 订单的商品编号和卖家编号组合通过数据库外键引用商品编号和发布者，防止订单卖家与商品发布者不一致。
- 交易概览统计全部商品的分类和校区分布、在售和已预订商品数，以及已完成订单数和价格合计；价格合计不是实际收款。

## 数据库与范围

- `Users`：演示用户和旧示例卖家；`Products`：商品；`Orders`：预约和交易记录；`Favorites`：用户收藏。
- 商品、订单和收藏通过外键关联用户或商品；收藏采用用户与商品联合主键；有效预约通过筛选唯一索引限制。
- 示例数据包含两个演示用户的在售商品，以及已取消、已完成订单，商品名称带【演示】标记。
- 不做登录、支付、物流、即时聊天、评价和管理员后台。页面继续使用白底、细边框、黑色价格与橙色主按钮。

## 本机演示

1. 按运行说明启动服务并打开网页。
2. 切换到小高，找到“【演示】小张的计算器”，收藏并刷新，检查收藏是否保留。
3. 预约该商品，在“我的订单”查看；切换小张后可以取消或确认完成。
4. 在 SSMS 中查看 `Users`、`Products`、`Orders` 和 `Favorites`，对照网页操作前后的记录变化。
